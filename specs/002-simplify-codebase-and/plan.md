## Testing & Regression Strategy

### UI Verification Strategy
To ensure the UI does not break during simplification:
1. **Automated Component Unit Tests**:
   - Run `bun run test:unit` in `src/frontend/` (covers `LiveAudioPlayer`, `AudioPlayer`, `audioState`, `audioVisuals`, `timecode`).
   - Every single test must pass cleanly before and after each UI file edit.
2. **Template & TypeScript Validation**:
   - Run `bun run check` (`svelte-check` and `tsc`) to guarantee that all bindings, event handlers, and prop interfaces in `.svelte` files are strictly valid with 0 errors.
3. **Production Static Build Gate**:
   - Run `bun run build` to verify Vite bundling and static adapter compilation to `src/frontend/build/`.
4. **Visual Layout Invariance**:
   - Simplify Tailwind classes without changing responsive breakpoints, color tokens, or layout hierarchies.

### Backend Verification Strategy
To ensure backend functionality and contracts remain 100% intact:
1. **Contract Invariance**:
   - Retain exact Gin route definitions, URL paths, HTTP verbs, and JSON structures in `router.go`.
2. **Backward-Compatible Delegation**:
   - When extracting logic into cleaner domain subpackages (such as `audioengine/conversion/`), retain forwarders where existing tests or callers rely on them.
3. **AST & Syntax Safety**:
   - Verify all Go source files have matching block braces, correct imports, and proper godoc formatting.
